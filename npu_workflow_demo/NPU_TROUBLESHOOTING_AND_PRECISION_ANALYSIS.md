# DeepX NPU 정밀도 트러블슈팅 및 98.78% 정합도 달성 종합 보고서

이 문서는 DeepX NPU(`DXNN`) 모델과 원본 PyTorch(`FP32`) 모델 간의 얼굴 임베딩 벡터 정밀도 비교(`step5_compare_pt_dxnn.py`) 과정에서 발생했던 유사도 저하 이슈들(`39.25% -> 56.02% -> 69.67% -> 94.32%`)의 핵심 기술적 원인과, 이를 완벽히 해결하여 최종 **98.78% (`0.987844`)** 정합도를 달성한 기술 규격을 정리한 공식 트러블슈팅 가이드입니다.

---

## 📌 정합도(Cosine Similarity) 변화 과정 요약

| 단계 | 발생 유사도 | 입력 규격 및 테스트 조건 | 판정 | 핵심 원인 |
|---|---|---|---|---|
| **1차** | **56.02%** | `CHW (1x3x112x112)` / `RGB uint8` / `lena.jpg` | ❌ 실패 | 텐서 차원 배열(`CHW`) 불일치 및 색상 채널 스왑 오류 |
| **2차** | **69.67%** | `CHW (1x3x112x112)` / `BGR uint8` / `lena.jpg` | ❌ 실패 | 텐서 차원 배열(`CHW`) 불일치 (NPU는 `NHWC`를 기대함) |
| **3차** | **39.25%** | `CHW (1x3x112x112)` / `RGB float32` 정규화 / `lena.jpg` | ❌ 폭락 | NPU 내부 2중 정규화 충돌 및 데이터 스케일 100배 왜곡 |
| **4차** | **94.32%** | `NHWC (1x112x112x3)` / `RGB uint8` / `lena.jpg` (일반 사진) | 🔵 우수 | 텐서 규격은 일치하나, 비정렬 사진 축소로 인한 양자화 클리핑 손실 |
| **최종** | **98.78%** | `NHWC (1x112x112x3)` / `RGB uint8` / `aligned_sample_1.jpg` | 🟢 **최우수** | **텐서 메모리 규격 완벽 일치 + 안면 인식 전용 정렬 얼굴 이미지 사용** |

## 🔍 핵심 문제 분석 및 해결 방안 (4대 핵심 원인)

### 1. 전처리 중복 수행 문제 (2중 정규화 및 채널 스왑 충돌)
* **문제 현상:**
  파이썬 추론 코드(`step4`, `step5`)에서 이미지의 `BGR -> RGB` 색상 변환이나 `(img / 255.0 - 0.5) / 0.5` 정규화를 수행한 후 NPU에 주입할 경우 유사도가 39%~69%대로 심각하게 왜곡됨.
* **근본 원인:**
  `step2_prepare_calibration.py`의 캘리브레이션 JSON 설정(`preprocessing`)에서 `"swap_rb": true`와 `"mean/std"` 정규화 옵션을 설정하여 컴파일했기 때문입니다. 이 경우 **DeepX NPU 하드웨어 신경망의 첫 번째 연산 레이어에 색상 스왑과 정규화 수식이 이미 내장**됩니다. 따라서 파이썬에서 정규화를 한 번 더 거치면 정규화가 중복(`Double Normalization`)되어 입력 데이터가 완전히 파손됩니다.
* **해결 규격:**
  > **"NPU 컴파일 JSON에 설정된 전처리(정규화, 채널스왑)는 파이썬 코드에서 절대 중복 수행하지 말고, 가공되지 않은 `uint8` 정수 원본 형태 그대로 주입해야 합니다."**

---

### 2. 텐서 메모리 형상 불일치 (`CHW` vs `NHWC` 레이아웃 오류)
* **문제 현상:**
  PyTorch의 일반적인 관습에 따라 `chw = np.transpose(img, (2, 0, 1))`을 적용한 후 `(1, 3, 112, 112)` `CHW` 형상으로 주입했을 때 39.25% ~ 69.67% 라는 오차가 발생함.
* **근본 원인:**
  DeepX NPU 컴파일러(`dx_compiler`)는 ONNX 모델을 NPU 명령어(`.dxnn`)로 변환할 때, 메모리 접근 효율과 하드웨어 가속기 구조에 맞추어 입력 텐서를 **`NHWC` (Channel-Last, `1 x 112 x 112 x 3`)** 형태로 컴파일합니다.
  만약 여기에 `CHW`(`1 x 3 x 112 x 112`) 바이트 배열을 주입하면, NPU 하드웨어는 메모리 상의 앞부분 `112x112`개 바이트를 모두 Red 채널 픽셀로 읽어버리기 때문에, 화면 상단 1/3은 Red 흑백, 중단 1/3은 Green 흑백, 하단 1/3은 Blue 흑백으로 쪼개진 기괴한 이미지가 신경망으로 전달됩니다.
* **해결 규격:**
  > **`np.transpose` 변환을 완전히 제거하고, OpenCV가 읽은 `(112, 112, 3)` 배열에 배치 차원만 추가한 `np.expand_dims(rgb_img, axis=0).astype(np.uint8)` (`NHWC`) 형상으로 주입해야 합니다.**

```python
# [검증 완료된 NPU 전처리 올바른 코드]
rgb_img = cv2.cvtColor(resized_img, cv2.COLOR_BGR2RGB)
input_tensor = np.expand_dims(rgb_img, axis=0).astype(np.uint8)  # Shape: (1, 112, 112, 3) NHWC
input_tensor = np.ascontiguousarray(input_tensor)
ie.run(input_tensor)
```

### 3. 비정렬 일반 사진(`lena.jpg`) 사용으로 인한 양자화 클리핑(Clipping) 손실
* **문제 현상:**
  NPU의 전처리 규격(`NHWC uint8`)을 완벽히 맞추었음에도 코사인 유사도가 98%가 아닌 94.32%에 정체됨.
* **근본 원인:**
  안면 인식 모델(`EdgeFace`)과 NPU 양자화 모델(`.dxnn`)은 **112x112 해상도의 정중앙에 양쪽 눈과 코, 입이 지정된 좌표로 크롭/정렬(`Face Alignment`)된 얼굴 이미지들의 데이터셋(`calibration_dataset`)**을 기준으로 활성화 값(`Activation`) 범위(`Zero-point / Scale`)를 8비트로 압축한 모델입니다.
  하지만 눈/코/입이 정렬되지 않고 깃털 모자와 배경이 가득 찬 일반 사진 `lena.jpg` (512x512)를 단순히 `cv2.resize`로 112x112로 억지 비율 축소하여 넣으면, 신경망 중간 레이어에서 양자화 캘리브레이션 범위를 크게 벗어나는 아웃라이어(`Outlier`)가 발생하고, 8비트 정수 변환 과정에서 클리핑(`Clipping`) 손실이 발생하여 약 4.5%의 오차가 생겼던 것입니다.
* **해결 규격:**
  > **안면 인식 전용으로 눈/코/입이 정렬된 112x112 크롭 얼굴 이미지(`test_images/aligned_sample_1.jpg`)를 주입한 결과, 클리핑 오차가 완전히 소멸하며 무려 98.78% (`0.987844`) 최우수 등급을 달성했습니다.**

### 4. 임베디드 보드와 호스트 간 Git Tracking 동기화 문제
* **문제 현상:**
  코드를 패치하고 `git pull`을 받았음에도 라즈베리파이(`rpi5`)에서 계속 `lena.jpg`가 실행되며 94.32%가 반복 출력됨.
* **근본 원인:**
  호스트에만 존재하던 `npu_calibration/aligned_faces_calibration/` 디렉토리가 `.gitignore` 설정으로 인해 라즈베리파이 보드로는 푸시/동기화되지 않았기 때문입니다. 그 결과 `step5_compare_pt_dxnn.py`에서 1~3순위 정렬 이미지 검색에 실패하고 fallback 우선순위인 4순위 `lena.jpg`가 강제로 로드되었습니다.
* **해결 규격:**
  > **정렬 완료된 검증용 얼굴 크롭 이미지 3장을 공식 워크플로우 폴더인 `npu_workflow_demo/test_images/aligned_sample_1~3.jpg`에 영구 복사 및 Git Commit 하여, 임베디드 보드에서도 즉시 98.78%를 검증할 수 있도록 조치했습니다.**

## 🛠️ 실무 개발 지침 (Checklist)

향후 DeepX NPU 안면 인식 및 다른 모델(`.dxnn`)을 개발/보정하실 때는 다음 3대 원칙을 꼭 기억해 주십시오:

1. **전처리 1회 수행 원칙:** `swap_rb: true` 및 `mean/std`가 설정된 컴파일 모델에는 절대 파이썬에서 `float32` 정규화를 2중으로 하지 마십시오.
2. **입력 텐서 레이아웃 확인:** `step4_npu_inference.py` 작성 시 NPU 컴파일러의 예상 입력 형상이 `NHWC(1, H, W, C)`인지 `NCHW(1, C, H, W)`인지 반드시 `ie.input_size()` 및 `shape`을 대조하십시오.
3. **캘리브레이션 데이터의 정합성:** 모델 보정(`step2_prepare_calibration.py`) 및 정밀도 검증(`step5_compare_pt_dxnn.py`) 시에는 반드시 실제 모델 배포 시와 동일한 전처리가 완료된 정렬 크롭 이미지(`Aligned Face`)를 사용하십시오.
